Chapter 01

Tell Your Story, Your Way

Story Builder Studio is built around a single idea: helping storytellers tell their story their way. Whether you are drafting a serialized screenplay, building an animated visual novel, or producing narrated video episodes, the studio keeps your scripts, storyboards, prompts, and generated media organized inside self-contained local project folders—without locking you into a single cloud platform or proprietary workflow.

Built natively with Qt 6 Quick/QML and C++20 across Windows (MSVC & LLVM-MinGW), Linux, and macOS, Story Builder Studio gives you flexible production methods you can mix and match to fit your hardware, budget, and creative vision:

1. Remote & Local REST APIs

Works immediately out of the box with zero extra AI libraries. Connect to Google Gemini, OpenAI, local Ollama servers, or custom OpenAI-compatible REST endpoints using environment-variable API keys.

2. Offline C++ Local Plugins

Run GGUF and ONNX models natively via optional plugins (llama.cpp, stable-diffusion.cpp, audio.cpp, sherpa-onnx) with no Python virtual environments required.

3. Custom-Trained Models

Drop your own fine-tuned LLMs, visual style LoRAs, and character checkpoints straight into your model directory to craft a distinctive, studio-grade aesthetic that is uniquely yours.

Unified Project Control: Every method feeds into the same Episode/Series project tree, Storyboard manager, and ISO-8601 Audit Ledger—so you can draft with a cloud LLM, render concept frames with a local FLUX checkpoint, and narrate with Kokoro TTS in one cohesive workspace.

Model Directory Topologies

When using optional local AI plugins, Story Builder Studio queries a standardized model tree in your system application data directory:

  • • Windows: %APPDATA%\StoryBuilderStudio\
  • • Linux: ~/.local/share/StoryBuilderStudio/
  • • macOS: ~/Library/Application Support/StoryBuilderStudio/

│   ├── Qwen3-8B-Q4_K_M.gguf
│   └── tokenizer.json
├── images/
│   └── flux/                     # FLUX image generation set (+ optional LoRAs)
│       ├── flux1-schnell-q4_k_m.gguf
│       ├── ae.safetensors
│       ├── clip_l.safetensors
│       └── t5-v1_1-xxl-encoder-Q5_K_M.gguf
├── video/
│   └── wan/                      # Wan 2.1 DiT video generation set
│       ├── wan2.1_t2v_1.3b-q4_k_m.gguf
│       ├── wan_2.1_vae.safetensors
│       └── umt5-xxl-encoder-Q5_K_M.gguf

Chapter 03

Unified Audit Ledger & UUIDs

To maintain strict record keeping across long-form projects, each generation produces a canonical ISO-8601 UTC timestamp (e.g., 2026-11-01T17:29:44.123Z). This string acts as a shared UUID linking prompt inputs, generated assets, and intermediate reasoning tokens.

prompt_history.json User Payload

Stores dispatched prompts, target modalities, and the linked timestamp.

{
  "timestamp": "2026-11-01T17:29:44.123Z",
  "category": "script",
  "promptText": "INT. CONTROL ROOM - NIGHT"
}
think_history.json Internal Reasoning

Captures reasoning tags (<think>) isolated from the clean response.

{
  "timestamp": "2026-11-01T17:29:44.123Z",
  "category": "script",
  "thinkText": "Need suspenseful dialogue pacing..."
}
Chapter 04

Prompt Composer & Attachment Tray

The PromptBuilder.qml component provides a unified interface across all local and remote engines. Attach character bibles, dialogue drafts, or reference frames directly into the generation pipeline.

1
Attachment Chip Tray:

Click Attach File(s) to attach .png, .jpg, .txt, or .md files. For video, attaching an image activates Image-to-Video (I2V) conditioning. For TTS, attaching scripts triggers continuous multi-sentence narration.

2
Reusable Prompt Option Plates:

Expand the options drawer to toggle filesystem .prompt modifiers (lighting, camera angles, pacing, genre styles) without retyping them on every shot.

3
Safe Dispatch Preview Modal:

Before invocation, the estimator displays projected runtime, memory footprint, and token counts so you can confirm or adjust settings before dispatching.

<think> Token Isolation

When running reasoning models (such as Qwen 3 / DeepSeek), internal thoughts inside <think>...</think> are intercepted in LocalLlmEngine::generateText(). They are stripped from the main editor stream and logged cleanly into think_history.json, keeping your working screenplay free of scratchpad clutter.

Script & Narrative Generation

Story Builder Studio supports both local and remote narrative backends through a unified driver contract:

  • Local LLM Plugin (GGUF): Uses llama.cpp with sliding-window context management. Supports Qwen, Llama, and your own fine-tuned GGUF weights placed in text/.
  • Remote REST Bridges: Built-in support for Google Gemini (GEMINI_API_KEY), OpenAI (OPENAI_API_KEY), local Ollama instances, and custom REST endpoints (environment variables ending in _API_KEY or _TOKEN).

Chapter 06

Visual Pipelines: FLUX.1 & Wan 2.1

FLUX.1 Schnell (Images)

Generates 4 candidate variations per prompt using CLIP-L and T5-XXL text encoders alongside the FLUX DiT and Autoencoder. Compatible with custom-trained style and character LoRAs.

  • • Latent Steps: 4 recommended (Schnell)
  • • CFG Scale: 1.0 (Schnell guidance)
  • • Output: 4 candidate thumbnails in Gallery

Wan 2.1 DiT (Video)

Supports both Text-to-Video (T2V) and Image-to-Video (I2V) conditioning. Output renders directly into your project's assets/video/ directory.

  • • T2V: Enter prompt and submit
  • • I2V: Attach a .png/.jpg keyframe
  • • Output: 16 FPS / 25 frames H.264 MP4

Chapter 08

Training Custom Models & Signature Looks

Off-the-shelf foundation models are great for prototyping, but modern AI media studios and independent creators train their own models and LoRAs to achieve a unique, signature look. Custom training is how you lock in recurring characters, bespoke art direction, consistent worldbuilding lore, and a narrative voice that doesn't look or sound like everyone else's default output.

You don't need a data center to start. Lightweight adapters (LoRAs) let you teach an existing base model a new visual style, character face, or writing style on a single consumer GPU—and then drop the trained weights straight into Story Builder Studio.

Recommended Open-Source Trainers

LLaMA-Factory Text / LLM

The go-to WebUI and CLI suite for fine-tuning Llama, Qwen, and Mistral models. Supports simple QLoRA instruction tuning for dialogue/script style as well as full CPT + SFT pipelines for deep worldbuilding lore.

github.com/hiyouga/LLaMA-Factory
OneTrainer All-in-One Visual

A clean desktop GUI built for training LoRAs and full fine-tunes across FLUX.1, Stable Diffusion, SDXL, and video DiTs. Ideal for starting with presets and gradually unlocking advanced schedulers, masking, and concept balancing.

github.com/Nerogar/OneTrainer
Kohya_ss & AI-Toolkit Diffusion LoRA

Industry-standard diffusion teaching tools. Ostris AI-Toolkit is purpose-built for fast FLUX.1 LoRA training with minimal config, while Kohya_ss offers deep GUI control for SDXL and Stable Diffusion workflows.

github.com/ostris/ai-toolkit github.com/bmaltais/kohya_ss

Training Basics: Start Simple, Scale as You Grow

The best way to learn model training is to run a small, focused experiment first and inspect the results inside Story Builder Studio before tackling complex multi-concept rigs.

1 Your First Visual Style / Character LoRA
  • Curate 15–30 clean images: Consistent subject or art style, varied angles/lighting, no watermarks.
  • Caption clearly: Pair each image with a matching .txt file using a unique trigger word (e.g., sbs_noir_style).
  • Train with defaults: Load the built-in FLUX/SD LoRA preset in OneTrainer or AI-Toolkit (rank 16, ~1,000–1,500 steps) and generate sample previews every 250 steps so you can stop before overfitting.
  • Test in Studio: Copy the resulting .safetensors adapter into your Studio image pipeline and evaluate how it responds to your prompt plates.
2 Your First Story / Voice LLM Fine-Tune
  • Build a small JSONL dataset: Collect 100–300 prompt-and-scene pairs written in your target pacing, formatting, and tone.
  • Run QLoRA in LLaMA-Factory: Launch the WebUI (llamafactory-cli webui), pick a 7B–8B base model, and run a 2–3 epoch SFT pass.
  • Merge & Quantize to GGUF: Export the merged model and convert it to Q4_K_M.gguf using llama.cpp's converter.
  • Drop into Studio: Place the .gguf and tokenizer.json inside StoryBuilderStudio/text/ and select it in Model Settings.
Scaling to Complex Setups: Once you are comfortable with single-concept LoRAs, these same trainers let you graduate to multi-character datasets with regularization images, masked loss for framing/viewpoints, Continued Pre-Training (CPT) on entire series bibles before SFT, and stacked LoRA weights—growing alongside your production ambitions.

Troubleshooting & Runtime FAQ

Local AI Engines Not Showing Up in Settings

Open Help → About to see which local plugins are loaded vs. missing. By default, Story Builder Studio builds in Core/REST-only mode so it compiles anywhere with just Qt 6. To include local C++ engines, rebuild using ./scripts/build.sh --all (Linux/macOS) or .\scripts\build.ps1 -All (Windows), or use --with="llama.cpp,kokoro" to pick specific libraries.

DLL Load Error: "Cannot load library ... qtquickdialogsplugin.dll / QtMultimedia"

Verify that Qt6QuickDialogs2.dll, Qt6Multimedia.dll, and Qt6MultimediaQuick.dll are present alongside the executable (or that your Qt bin/ directory is on PATH via scripts/run.bat), and that the QtQuick/Dialogs/ and QtMultimedia/ QML folders are intact.

Local GGUF Model Takes a Long Time to Load on Windows

Windows Defender Real-Time Protection scans multi-gigabyte .gguf files on initial read. Add your %APPDATA%\StoryBuilderStudio\ folder to Windows Defender's Exclusions list, and keep context size bounded to 4096 or 8192 unless you specifically need a larger window.

Where do deleted assets go?

Assets deleted via the workspace context menu are permanently removed from the active project's assets/ directory after a strict path verification check ensuring no files outside the project root can be affected.
